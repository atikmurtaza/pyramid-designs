# ADR 0016: Public intake admission and unproven proxy identity

Date: 2026-09-28. Status: Phase 2I-D implementation decision; production activation remains prohibited.

## Evidence and decision before implementation

The committed baseline a6017ba uses one PostgreSQL RateLimitBucket row for both application types and both encodings: 20 attempts per 60 seconds, capped at 21. Admission commits separately before parsing, so failed validation and exact/conflicting retries consume budget. Production intake is unconditionally closed. Multipart bytes and concurrent parsers are bounded, but native formData currently materializes parts before counting them. Drive ID allocation precedes structured validation. Those are the narrow correction targets.

Keep the existing table and budget. Use database statement time for runtime rollover, retain bounded single-row storage, and fail closed on unavailable/invalid admission results. A test-only clock override may exercise rollover. Add a small process concurrency guard before DB admission to bound pending pool work; it supplements, never replaces, the durable authority. A global budget can be exhausted by one actor. It is conservative protection for initial volume, not a network DDoS guarantee or a fair client quota.

Order: bounded URL/Host/Origin and the existing production-closed gate; remaining fixed method/path/query and header bounds; process admission; separately committed DB budget; bounded body read; strict multipart envelope/field validation; PDF validation/hash; authoritative transactional application validation; external storage and fenced finalization. No candidate email, arbitrary job/key dimension, fingerprint or forwarding header becomes a limiter identity. All retries reaching durable admission consume the same budget.

Do not trust X-Forwarded-For, X-Real-IP, Forwarded, CF-Connecting-IP or forwarded host/protocol as client identity. Current reviewed Hostinger Node deployment/options pages establish managed Node hosting, not header replacement, unforgeable hop identity, stable proxy ranges, origin bypass protection or a native trusted client-IP primitive. Existing runtime evidence proves bounded upload transport, not proxy provenance. Per-IP enforcement is UNAVAILABLE_UNTIL_TRUSTED_PROXY_PROVEN. No raw IP or keyed tracking identity is introduced. The implementation record defines the later deployment proof.

Retain the accepted Turnstile requirement: challenge-free production is not justified by this global budget and unproven proxy. Implement a server-only provider-neutral verification result and native-fetch Turnstile contract, with explicit configuration, fixed endpoint/action, hostname validation, single-use/expiry checks, timeout and response bounds. No remoteip is supplied. No synthetic verifier exists in runtime source. Current loopback synthetic intake remains an explicitly development/test-only rehearsal without provider calls; production cannot enter that path even with forged loopback headers or configured test values. The adapter does not activate intake. Production widget/accessibility/CSP, real credentials, provider validation and legal review remain separate gates; no UI or permissive CSP changes are warranted while intake is closed.

Admission must precede external challenge verification in a future enabled production route, so a challenge-provider outage/flood cannot amplify unbounded outbound work. Every retry will need a fresh token; tokens stay outside the application idempotency digest and are never logged or persisted. Provider timeout/unknown response denies mutation; no retry inside the adapter, cached token acceptance or idempotency bypass. This phase establishes the contract, not a production route bypass.

Retain 24 KiB structured payloads, 50 answers, existing string limits, 5 MiB PDF and 5 MiB + 32 KiB multipart envelope. Count raw parts and bound headers/field bytes before native parsing. Reject unknown/duplicate fields and malformed framing; validate structured fields before PDF inspection. Move authoritative application validation ahead of Drive allocation without holding a database connection over provider I/O; pending file-required applications remain safely non-reviewable and idempotently recoverable.

No migration, dependency, production configuration, real email, live Google operation or deployment is required. Existing consent/file evidence, notification eligibility, staff authorization and RLS are preserved. New documentation supersedes earlier speculative honeypot/timing and per-identity limit lists: those are not independent security guarantees and are not added without evidence of benefit. Turnstile data processing is not privacy-neutral; approved notices/processor/legal review remain mandatory.
